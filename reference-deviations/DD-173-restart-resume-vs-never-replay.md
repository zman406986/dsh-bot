# DD-173 — Restart handling: quiesce-and-resume vs rebuild-and-never-replay
- **Area:** A20 session & durability
- **Type:** deliberate-divergence
- **Date:** 2026-09-23

## What the reference does
On an upgrade/restart the reference does two things in sequence, and both are aimed at hiding the restart from the user. First it quiesces running work — the module exposes a quiesce entry point for the upgrade path and a second one for the recreate path (`the reference tree's source/host/extensions/transcript/upgrade-recreate-resume.ts` around lines 36 and 184), and the recreate-side quiesce returns, alongside the quiescing set, the agents awaiting resume and the durable pending-wake markers to carry forward (around lines 184–201). Then, on the far side, it resumes the interrupted sessions itself: it enumerates the resume-pending agents and dispatches each one through a hidden run (around lines 101–158) — the runner call is explicitly marked hidden (around line 142) — driven by a resume instruction composed per source tag (around lines 11–18), where the source classification distinguishes an ordinary turn, an automation-driven run, a background revival, and a handoff-style resume (around lines 124–146). The resume instruction tells the resumed agent its conversation is intact, to continue from the point of interruption, not to repeat a step that already completed an action, and that nothing reaches the user outside the user-facing send path (around lines 11–18). Wake context is not lost across the restart: the pending wakes are read from the pending-wake store (`the reference tree's source/host/extensions/transcript/sand-pending-wake-store.ts`) and carried across the recreate boundary (around lines 184–201), with a dedicated carry marker type. A resume that fails is reported as a failed resume rather than silently dropped (around line 168). Net effect: the user does not see the interruption, and the resumed turn does not appear on the conversational surface.

## What the current build does
The build takes the same event and makes the opposite choice. `rebuildFromDurability` in `src/core/multitask.ts` (from line 866) rebuilds the dispatcher ledger from persisted worker markers and explicitly never resumes interrupted work. Terminal markers are restored onto the roster (around lines 902–918); a marker whose worker was live at crash time becomes an explicit unknown-state hold rather than a guess (around lines 877–900) — and per the recorded ticket-59 ruling (register B-1) that hold keeps its stream key occupied, so the one-worker-per-stream invariant survives the restart instead of the build throwing away its only handle on a possibly-live worker (around lines 885–899). The interruption is then surfaced, not hidden: the restart-notice module at `src/adapter/restart-notice.ts` injects one conversational notice stating unknown-state workers as unknown — never replayed, never resumed, never claimed done — with ids and transcript pointers, and stating restored terminal rows plainly; an empty rebuild report emits nothing at all, and a marker store that cannot be read degrades to one notice reading "nothing was restored and nothing was replayed" while activation still succeeds (module header, lines 3–35). Durability read/write lives in `src/core/durability.ts`. The recorded ruling is ADR-0012, "Restart replays durability, never work": the dispatcher replays durable records only, and never re-runs a worker, re-dispatches work, or invents state the markers do not carry. The build's own comment on the rebuild path (around lines 855–864) records the non-use of the host's continuable-session cold-resume as a core design decision rather than an oversight, and states that reversing it is a separate decision and not a side effect of this path.

## The deviation
Both systems face the same event — a restart — and disagree about interrupted work, deliberately. The reference resolves the interruption by resuming it, out of the user's sight. The build resolves it by refusing to resume and saying so out loud. The build's side is recorded and principled on two independent grounds: ADR-0010's rule that displayed state must reflect real state, which is why the build refuses to silently re-run work or pretend it continued and why it emits a notice instead of hiding the interruption; and ADR-0012, which fixes restart as durability replay and never work replay. The build therefore does not merely lack the reference's resume machinery — it is committed to not having it. Read as a fidelity gap this looks like missing behavior; read against the authority stack it is a ruled choice, and the notice is a positive feature the reference does not have.

## Verdict: DO-NOT-INCORPORATE
ADR-0012 is decisive for the resume half: restart replays durability, never work, and the dispatcher never re-runs a worker, re-dispatches work, or invents state the markers do not carry — adopting the reference's resume would directly reverse that ruling rather than extend it. ADR-0010's rule that displayed state must reflect real state independently favors the build's unknown-state notice over a silent resume, since a hidden resume is exactly the claim that work continued when it may not have. And the reference's resume is hidden by construction (the run is marked hidden, `the reference tree's source/host/extensions/transcript/upgrade-recreate-resume.ts` around line 142), which ADR-0018 A4's no-hidden-sends rule independently disfavors. This deviation is therefore ruled, not unruled: the resume half is closed by ADR-0012 and reinforced by ADR-0018 A4, and the build's own rebuild-path comment already records that reversing the non-resume posture is a separate decision (multitask.ts around lines 862–864).

## Incorporation notes
- **Where it would live:** Nothing to add. If ever reversed, the touch points are the rebuild path in `src/core/multitask.ts` (`rebuildFromDurability`, from line 866), the activation hook that injects the restart notice in `src/adapter/restart-notice.ts`, and the marker read/write surface in `src/core/durability.ts`.
- **Constraints:** Any resume design would have to survive four recorded constraints at once: ADR-0012 (no re-running work on restart), ADR-0010 (the interruption must be stated plainly, not hidden), ADR-0018 A4 (no hidden sends), and ticket 59 register B-1 (an unknown-state hold keeps its stream key occupied). It would also have to preserve the activation-generation guards that stop a stale rebuild chain from publishing or injecting anything.
- **License note:** ADR-0018 B9 — re-derive independently; no verbatim copying from the reference tree.
- **Effort/risk:** L + the work is not the code but the reversal: it means superseding ADR-0012, re-opening the unknown-state reporting contract (ticket 59) and the activation-generation guards, to buy a behavior the build deliberately rejects because it would misreport state.
