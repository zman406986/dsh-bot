# DD-175 — Group sessions and shared rooms
- **Area:** A20 session & durability
- **Type:** deliberate-divergence
- **Date:** 2026-09-23

## What the reference does
The reference supports multi-party agent sessions: several agents share a room, with a shared-room configuration layer, group-chat orchestration and glue, and a send-side fan-out path that delivers one message to every member. The group-chat glue and the shared-rooms modules together are roughly 48 KB of source (23.7 KB and 24.9 KB respectively), with further group/room storage and orchestration modules alongside them. Group context is a first-class branch of the run path, not an application of the ordinary one-to-one path: for a session that belongs to a shared room, the per-member turn pipeline appends a shared-room instruction to the member's system prompt before the turn runs (`the reference tree's source/host/extensions/transcript/group-chat-glue.ts:330-340`). The research pass recorded that group sends are also exempted from the normal acknowledgement obligation on the send side (anchor: group-chat-glue.ts around lines 334-336; see Evidence for what the spot-check confirmed).

## What the current build does
The peer channel is strictly point-to-point between dispatchers. The peer-inbox module's envelope validation admits only a single-agent target; every other target shape — the retired group and broadcast kinds — is refused as an invalid envelope (`src/core/peer-inbox.ts:89-95`, whose comment records the C14 classification from ticket 70 §3). The peer send tool exposes a one-to-one send with a single fixed direct-conversation identifier and a text ceiling (`src/core/tools.ts:623-676`), and the multitask core wires the inbox for one delivered turn per message id (`src/core/multitask.ts:241-257`, `319-332`). There is no room, no membership list, and no multi-party session concept anywhere in the peer path.

## The deviation
The build deliberately narrows the peer channel to agent-to-agent, point-to-point messaging and carries no group-room concept at all. The refusal of any target that is not a single agent is the channel's contract, not a gap: it is the implementation of a recorded exception rather than an omission awaiting work. The 1:1 surface itself is covered by the sibling deviation DD-162 (inter-agent messaging surface); DD-093 (org-chart network) covers the neighbouring set of excluded identity features.

## Verdict: DO-NOT-INCORPORATE
ADR-0018 is an accepted, human-ruled ADR (authority tier 2), and its exception C14 explicitly names "no group rooms" alongside the excluded org-chart/routines/memory class (`docs/adr/0018-imitate-reference-in-entirety-exception-list.md:29`) — the closest recorded ruling does cover group rooms by name, so no inference beyond its text is needed. The architecture independently rules it out: the build is one dispatcher plus transient workers, and multi-party rooms presuppose a persistent roster of agents, which C13 (no agent-identity roster, same ADR, line 28) also excludes. Nothing in the authority stack argues for reopening; a reversal would have to start by amending C14.

## Incorporation notes
- **Where it would live:** a room/membership layer spanning `src/core/peer-inbox.ts`, `src/core/multitask.ts`, and the peer send tool in `src/core/tools.ts`, plus a durable roster — the roster being the part C13 independently excludes.
- **Constraints:** contradicts ADR-0018 C14 (accepted, human-ruled) and C13; presupposes a persistent agent roster the dispatcher-plus-transient-worker model rejects; a group wake path would also break the rule that there is only one wake kind (C15) and the one-to-one acknowledgement and liveness boundaries set by ticket 70 §2/§3.
- **License note:** ADR-0018 B9 — re-derive independently; no verbatim copying from the reference tree.
- **Effort/risk:** L — not because the code is large, but because adopting it means reversing a human-ruled exception before any implementation question is even reachable.
- **Key reference anchors:** `the reference tree's source/host/extensions/transcript/group-chat-glue.ts` (shared-room branch at 330-340; send-path anchor around 334-336), `the reference tree's source/host/extensions/transcript/shared-rooms.ts`, `the reference tree's source/host/extensions/transcript/group-chat-orchestrator.ts`, `the reference tree's source/host/extensions/transcript/send-group-fanout.ts`, `the reference tree's source/host/groups/group-chat.ts`, `the reference tree's source/host/groups/group-store.ts`, `the reference tree's source/host/groups/remote-room-store.ts`.
