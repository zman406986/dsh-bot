# DD-070 — In-transcript Slack draft card vs none
- **Area:** message cards (A10)
- **Type:** missing-feature
- **Date:** 2026-09-23

## What the reference does
The reference transcript-card registry includes a slack-draft send-message leaf, recovered as a lazy-loaded view with its own evidence annotation pointing at a slack-draft chunk in the shipped renderer bundle (`registry.ts`, lazy-view evidence line and the slack-draft metadata entry). The view (`slack-draft.tsx`) renders an editable Slack composer inline in the conversation transcript: a header row with a Slack logo icon and a live send-status line (ready to send / sending), a Workspace row, a target row labelled To, and a Thread row that either announces a new message or a reply within the named thread. The body is a textarea with a write-a-message placeholder; when the body exceeds 8 visual lines while collapsed it shows a plain-text preview plus a show-more/show-less toggle. Send is enabled only while the entry is editable and the body has non-whitespace content; Discard sits beside it. Once the entry's draft state flips to sent, the whole form is replaced by a compact sent confirmation: Slack logo, a Slack-message-sent line, and a first-line-bounded preview naming the send target and the body.

## What the current build does
The build has no Slack surface at all. A case-insensitive search for "slack" across `src/` and `client/` returns zero matches. The build's transcript surface is the web client conversation feed (`src/client/conversation.tsx`, `src/client/conversation-feed.ts`, `src/client/conversation-store.ts`), which renders worker/task conversation but has no message-card registry, no draft-card concept, and no notion of composing messages to external chat targets. There is no Slack connector, no send/discard lifecycle state on any transcript entry, and nothing corresponding to the draft payload shape (workspace/target/thread/body).

## The deviation
The reference embeds an editable, stateful Slack draft card directly in the transcript flow (compose → collapse/expand → sending → sent preview); the build has nothing in that slot. The gap is real but the card is only half the story: the reference's own evidence annotations record that the shipped send and discard callbacks were empty stubs, so even there the card was a presentation shell over a Slack send pipeline that lived (if at all) outside the recovered renderer code. The build would need both a Slack connector backend and a draft-state lifecycle on transcript entries before this card could do anything.

## Verdict: DO-NOT-INCORPORATE
The card is a front-end shell whose reference implementation shipped with empty send/discard callbacks, so incorporating it would add dead UI over a Slack connector backend the build entirely lacks — and no recorded ADR or PRD amendment brings a Slack connector into dsh scope; it sits adjacent to the C14 non-goals list (the ADR-0018 entry that rules out an org chart, routines and automations, per-agent memory, and group rooms) around peripheral integrations. The one idea worth keeping is the generic pattern (an editable draft card with a collapse threshold and a sent-state confirmation rendered inline in the transcript), which is worth revisiting only if the human rules some external-target connector into scope — that ruling does not exist, so per the ruling order defined in `docs/agents-rulebook.md` this is a do-not-incorporate rather than a silent partial pick.

## Incorporation notes
- **Where it would live:** if ever revisited, the composer view would belong to the web client transcript layer (`src/client/conversation.tsx` / `src/client/conversation-feed.ts`), with the draft payload shape and send/discard state machine on the core transcript-entry types (`src/core/types.ts`) — both currently have no card registry to hang it on.
- **Constraints:** requires a Slack connector backend (workspace/target/thread resolution plus a real send path) that does not exist and is not in scope; the reference's own send/discard handlers were stubs, so there is no working backend design to recover from it either; any future version must be re-derived from scratch.
- **License note:** ADR-0018 B9 — re-derive independently; no verbatim copying from the reference tree.
- **Effort/risk:** M — the card itself is small, but it is unusable without an out-of-scope Slack connector (an L-sized backend), and the risk is scope creep past the PRD plus shipping a composer that cannot send.
- **Key reference anchors:** `the reference tree's frontend/src/recovered/features/conversation/cards/transcript-card/views/slack-draft.tsx` (composer form, collapse-over-8-lines toggle, the sent-confirmation block, empty send/discard callbacks per evidence comments); `the reference tree's frontend/src/recovered/features/conversation/cards/transcript-card/registry.ts` (lazy-view evidence line; the slack-draft metadata entry); `the reference tree's frontend/src/recovered/features/conversation/cards/transcript-card/protocol.ts` (the slack-draft message type and projection).
