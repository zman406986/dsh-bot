# DD-195 — Durable-block preservation across compaction
- **Area:** A24 context management
- **Type:** behavior-delta
- **Date:** 2026-09-23

## What the reference does
Because the reference owns conversation compaction, it can also decide what must survive it. One module in its agent-summarization package declares a closed set of seven block kinds — the mode prompt, the project-root prompt, the current plan, the transcript location, the automation context, the todo content, and the skills blocks — and, keyed by which summarizer is running (the generic path plus the provider-specific compactors), a placement table saying which kinds are emitted ahead of the summary and which follow it. The sets differ per summarizer: the generic and one provider path carry all seven; others carry a subset and drop the plan block entirely. Each kind has a renderer that pulls its text out of the enrichments the caller supplies; several wrap their payload in a short framing note telling the model what the block is and how to treat it — the plan block, for instance, is re-framed as work to continue rather than as text to be summarized. Empty blocks are skipped, duplicates collapse, and the surviving blocks are concatenated onto the summary text with a fixed separator (`the reference tree's source/packages/agent-summarization/durable-blocks.ts:11-18` for the kind set, `:20-41` for the placement table, `:91-144` for the renderers, `:151-188` for render/append/prepend). Four call sites consume it, each passing its own summarizer key: the external path in the main handler and the three provider/self-summary handlers (`the reference tree's summarization-handler.ts:1079-1083`; `the reference tree's source/packages/agent/self-summary/self-summary-handler.ts:549-558`, `anthropic-compaction-handler.ts:213-221`, `openai-compaction-handler.ts:182-186`).

The latest image is preserved by the same package through a separate path: a dedicated module walks the conversation backwards for the most recent image part, normalizes it into a data URL, and hands it back to the handler, which attaches a named note to it so the model reads it as the last known visual state rather than as new input (`the reference tree's source/packages/agent-summarization/latest-image.ts:24,33-47,62-77`; the note constant at `the reference tree's summarization-handler.ts:796`).

## What the current build does
**Absent as a mechanism.** The build does not own compaction (the parent finding is DD-192, `reference-deviations/DD-192-llm-context-summarization.md`), so it has nothing of that kind to offer a compactor. What it has instead is three substitutes, each in a different place:

1. **A static system-position contract.** The worker contract is delivered at a system position: the adapter passes it as the spawn request's persona (`src/adapter/cordis-dsh-host.ts:629-668`), which the host renders into a system-prompt section recomputed every turn. `src/worker/prompt.ts:5-12` states the consequence in the file's own header — the contract survives compaction by construction, and no text needs appending to steer messages. This is the D-1 fix, with D-2 dissolved behind it (`docs/research/dsh-core-loop-deviations.md:30-31`).
2. **A restatement practice.** At the start of every dispatcher turn the adapter re-injects a reminder carrying the ledger plus a condensed standing-rules block (`src/adapter/parent-agent.ts:258-267` calling `assembleTurnReminder`, `src/core/policy/assembler.ts:60-71`; the rules text at `src/core/policy/prompts.ts:111-121`). The rules block is emitted unconditionally — an empty ledger still gets the rules, with the ledger line collapsing to a placeholder. The full policy section is a different thing: it is injected **once**, at activation, as queued plugin context rather than a system section (`src/adapter/parent-agent.ts:321-323`; `tryInject` at `:49-57` queues a next-step context message, it does not place a system section).
3. **A truncation marker.** When the build clips a report it appends a marker of a fixed shape: an ellipsis-led, bracketed annotation that names the fact of truncation and the shown/total character counts, optionally followed by a pointer to the full transcript when one exists (`src/core/report-clamp.ts:47-54`, applied by `clampReport` at `:60-74`). It fires only on the over-bound path; an unclipped report carries no marker.

## The deviation
This is one problem solved two ways. The reference **marks content durable and asks the compactor to respect the marks**: nothing is re-sent, the cost is paid only at compaction time, and the guarantee holds exactly as long as the compactor cooperates — the marks are inert text otherwise. The build **re-injects its standing rules every turn so they cannot be lost, and marks truncation where it happens**: it never asks a compactor for anything, so the guarantee does not depend on cooperation, but it pays prompt weight on every turn of every dispatcher session, and the marker describes a loss that has already occurred rather than preventing one. On robustness the build's restatement is arguably the stronger of the two, because it is indifferent to how the host compacts; on cost the reference's approach is the cheaper one.

One asymmetry is worth naming, and it is not the one that looks obvious. The plausible gap — that worker prompts are composed once and never restated, so a worker's contract would be unprotected — does **not** hold: the persona section is recomputed every turn, so the worker side carries the same survival-by-construction property as the restatement practice, and D-2 was dissolved for exactly this reason (`docs/research/dsh-core-loop-deviations.md:31`). The real asymmetry is on the dispatcher side, where the protection is **partial by design**: only the condensed standing-rules block is restated each turn; the full policy section is injected once as queued context, so its detail — the tool guidance, the plain-language stop rule, the no-board rule — depends on surviving compaction, while the core operating rules do not. The reference's durable blocks, by contrast, are carried whole. The second asymmetry is scope: the build's marker covers the report body the build itself hands back into the dispatcher's context, not the conversation at large.

## Verdict: DO-NOT-INCORPORATE
No recorded ruling covers durable-block preservation: ADR-0018's exception list is exhaustive and says nothing about compaction survival (`docs/adr/0018-imitate-reference-in-entirety-exception-list.md:19-42`), so this is not an enumerated deviation — but the mechanism is also unreachable on the build. The host owns the conversation and its compaction, and the build is a plugin with no way into the compactor; a plugin that rendered blocks into a compaction prompt would be doing the host's job, the same approved-by-necessity shape DD-192 recorded for summarization itself. The nearest recorded rulings are exception 17 (**U-F**, `:39`), which settles the build's context hygiene as inline clamping rather than spilling to storage with prompt-side references, and exception 10 (**D21**, `:32`), which approves the clamp bounds the marker depends on. The build's substitutes are recorded practices, not absences: D-1's system-position placement and the per-turn reminder already cover what must outlive compaction. If a register item were ever wanted here it would be a new one requiring a human ruling, since nothing on ADR-0018's list covers it.

## Incorporation notes
- **Where it would live:** Nowhere as a mechanism — there is no compactor in this build to hand marks to. The only build-side places that bear on the question are the contract texts and the clamp module: `src/worker/prompt.ts`, `src/core/policy/prompts.ts` (the condensed rules block versus the full policy section), `src/core/policy/assembler.ts`, and `src/core/report-clamp.ts`.
- **Constraints:** Any build-side move here is a claim about survival, not a mechanism, and the claim has to be tested against real host compaction behaviour rather than asserted. The one live lever is the wording and position of the build's own injected sections — and the standing-rules block exists precisely to be cheap, so widening it trades prompt weight against coverage on every turn.
