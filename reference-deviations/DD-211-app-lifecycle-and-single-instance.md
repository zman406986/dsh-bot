# DD-211 — App lifecycle and single-instance enforcement
- **Area:** A27 platform integration
- **Type:** missing-feature
- **Date:** 2026-09-23

## What the reference does
The desktop main-process entry installs an application lifecycle policy in one place (the reference tree's `source/electron-main/main.ts`). It takes a single-instance lock and skips the lock when the app is running unpackaged, so a development build can coexist with an installed one (line 248); when it is not the primary instance it quits immediately (line 249). The policy then wires four events. A second-instance event either brings the existing window forward — restoring it if minimized, then focusing it — when the incoming arguments carry no link candidates, or forwards each candidate into the link pipeline (lines 354–364); the link half is already filed as DD-210. An activation event (the macOS dock re-entry) recreates the main window only when no windows remain (lines 416–418). A window-all-closed event quits the app on every platform except macOS (lines 422–424). A before-quit event marks the app as quitting, cancels any in-flight startup, offers a pre-quit hook the chance to veto the quit so background work can finish, and only then disposes services and drops the window reference (lines 425–434). Quitting state is exposed as a reader on the runtime handle (line 438) and consumed well beyond shutdown bookkeeping: the coordinator's telemetry classifies a disconnect cause by consulting it first, falling through to connectivity and a rebuild-in-flight flag so that a deliberate user quit is distinguished from a client going offline and from a host restart (the reference tree's `source/electron-main/coordinator/coordinator-telemetry.ts:7`). Window focus state is also pushed to the renderer through a dedicated sync entry (line 172).

## What the current build does
Absent by construction. The build is a Cordis plugin, not an application: `package.json:2-6` declares a plugin manifest (name, description, version, module type) with no process, no window, and no entry point that owns a lifetime. It therefore has no single-instance lock to take, no activate/quit/relaunch path, and no background-residency decision to make. The build's host interface, `src/adapter/cordis-dsh-host.ts:159-224`, is a structural interface over host services (tool registry, command registry, live agents, session wiring) — a capability surface, not an application-shell API; nothing in it exposes single-instance election, window activation, or quit sequencing, so there is no interface through which the plugin could participate even if it wanted to. The build's restart story lives elsewhere entirely: the in-chat restart notice at `src/adapter/restart-notice.ts` plus durability replay, ruled by ADR-0012 ("Restart replays durability, never work"). That half is already filed as DD-173 and is cross-referenced here rather than re-derived.

## The deviation
The reference owns a process and its lifetime; the build owns neither and cannot. Single-instance election, window activation, and quit sequencing are application-shell duties that the host (dsh) performs on the build's behalf, and the deviation is one of reach rather than of choice: there is no host interface for them, so a plugin-side implementation is not merely unbuilt but unbuildable. The build does have one product-relevant leftover from the reference's quit-cause classification — attributing a disconnect to a deliberate user quit rather than a network drop or a host restart is a diagnostic distinction with value outside a shell — but the build's equivalent signal is its restart notice and durability replay, not a quitting flag, and it is named here only as that leftover.

## Verdict: DO-NOT-INCORPORATE
ADR-0020 (draft, non-human-approved) rules on the application shell, and its rejected-options table records a native/Electron desktop shell as a PRD non-goal — "do not chase Sand/Cursor/Grok Bot binary or UI parity" — excluded without further study (`docs/adr/0020-wrapper-shell-vehicle-own-frame-over-shipped-runtime-draft-nonhuman-approved.md:28`). That exclusion is exactly the lifecycle mechanics described above: a single-instance lock, an activation handler, and quit sequencing exist only inside an application shell, so the ruling covers them. The build cannot incorporate them in any case, since a plugin has no process to lock or quit and the host owns the app shell. The restart half is separately ruled by ADR-0012 and already filed as DD-173, so it is cross-referenced rather than re-argued. No recorded ruling covers a shell reversal beyond ADR-0020's own status note that the shell choice was later superseded (line 3); if a shell is ever elected, this file should be re-opened rather than treated as settled.

## Incorporation notes
- **Where it would live:** Nothing to add. The build has no application entry point; if a shell were ever elected, lifecycle code would belong to that new application shell rather than to any existing module under `src/`.
- **Constraints:** A plugin has no process lifecycle, and the host interface (`src/adapter/cordis-dsh-host.ts:159-224`) exposes no lifecycle hook to attach to. The restart half is closed by ADR-0012 and carries DD-173's constraints (no work replay, honest unknown-state notice, stream-key hold, activation-generation guards). Any shell election would also have to survive ADR-0018's exception list, which assigns the session/job store (A5) and the send path (A4) to dsh.
- **License note:** ADR-0018 B9 — re-derive independently; no verbatim copying from the reference tree.
- **Effort/risk:** L + not code but a reversal of the shell decision: it requires replacing ADR-0020's shell exclusion and building an application shell the plugin architecture does not have, to buy lifecycle behavior the host already performs.
- **Key reference anchors:** single-instance lock and immediate quit for a secondary instance (the reference tree's `source/electron-main/main.ts:248-249`); second-instance focus/restore and link-candidate forwarding (354–364); activate-driven window recreation (416–418); off-mac quit on window-all-closed (422–424); before-quit marking, startup cancel, pre-quit veto hook, service disposal (425–434); quitting reader on the runtime handle (438); window-focus sync to the renderer (172); disconnect-cause classification consulting the quitting flag (the reference tree's `source/electron-main/coordinator/coordinator-telemetry.ts:7`).
