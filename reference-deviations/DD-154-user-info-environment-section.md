# DD-154 — Environment/user-info section in the system prompt
- **Area:** A18 prompt sections
- **Type:** missing-feature
- **Date:** 2026-09-23

## What the reference does
The reference assembles a single prompt section it titles as a user-info section and places it in the system prompt. Its content is an inventory of the execution environment: the operating-system version; the shell in use (with a fallback when none is reported); the workspace path or paths, each with a worktree warning when the path lies inside a managed worktree tree, plus a warning against searching or editing non-primary worktrees and an extra note when the working directory is the home directory; a line stating whether the directory is a git repository, including intermediate wording for two detection states still being determined (partially known, and unknown); the terminals folder; any mounted agent stores; today's date; agent notes folders (shared notes, conversation notes, or a meta-agent notes directory depending on mode); and a closing preference line telling the agent to favor absolute over relative paths in tool arguments.

A per-model variant of the same section reorders the members and extends the set — it adds the notes-path lines conditionally on mode and meta-notes enablement, and it moves the absolute-path preference line to the end of a differently ordered list. Section membership is also switched by flags the caller passes in (whether to display the date, whether to display the git status line), and individual lines are left out when their value is absent.

## What the current build does
Absent. The build's prompt assembly emits no environment/user-info section. Its policy assemblers produce exactly four things: the dispatcher policy section, the per-turn reminder (ledger plus standing rules), the wake-turn instructions, and the access section; none of these reports OS, shell, workspace, git status, date, folders, or path preferences. Its own copy is limited to the standing rules and the worker safety text. Environment facts are expected to arrive from the host rather than from the build's own prompt text, and the build's worker contract states this delegation explicitly: it declines to repeat the host's own fixed delegation-scope statement because the guarantee is the host's and is already stated once, and repeating it would spend tokens every turn and risk the two texts drifting apart.

## The deviation
The reference owns its environment reporting; the build delegates it. This is a genuine structural difference in prompt ownership, not merely a missing string: the reference computes and renders the environment inside its own prompt tree, while the build treats environment facts as host-supplied context and writes only alongside them. Two consequences follow. First, whether the build has an equivalent capability at all depends on what the host guarantees — if the host already injects environment facts into every session, the build's "absence" is a division of labor and there is nothing to add; if the host does not, then the reference has a capability the build genuinely lacks. Second, the reference's section is a matter of section assembly (ordering, gating flags, per-model variants) as much as a matter of content, so the two variants of the deviation should be read separately.

The nuances worth carrying even if the bulk is not copied: the worktree warnings and the absolute-path preference are behavioral guidance about how tool calls are made, not passive environment facts, and are therefore the parts least likely to be supplied by a host's environment report.

## Verdict: ADAPT
No recorded ruling in the authority stack names an environment section. The ADRs, the PRD, and the read-before guides address delegation boundaries, tool registration, and prompt-section ownership elsewhere, but none rules on whether the build should itself emit environment/user-info content; this is uncovered, and the guidance on record for uncovered conflicts is to stop and ask rather than pick silently — so this verdict is a recommendation, not a settled decision.

ADAPT rather than INCORPORATE because the environment-fact bulk is very likely already the host's job: the build's own worker contract documents the deliberate rule of not repeating statements the host owns, and duplicating OS/date/paths would run directly against it. What is left, and what is worth carrying independently, is the behavioral guidance — the worktree warning and the absolute-path preference — which tells the agent how to shape tool calls rather than informing it of a fact, and which a host environment report would not necessarily phrase. ADAPT rather than DO-NOT-INCORPORATE because that guidance is a real, low-cost behavioral improvement that would be lost by dropping the deviation entirely.
