# DD-144 — Ack-first turn rhythm with silence policing vs no turn-rhythm copy
- **Area:** system prompts / persona (A17)
- **Type:** missing-feature (persona + runtime reminders)
- **Date:** 2026-09-23

## What the reference does
The reference treats the shape of a turn itself as a first-class persona rule, not an incidental. Its core operating text fixes an order of actions: on any turn a person opened, the very first action is a plain text send addressed to that message — before any tool call, browse, or long private reasoning; a real-work request gets a short acknowledgement naming the first step, then work. It separates two duties explicitly: the opening acknowledgement never discharges the duty to deliver the result later, and ending a turn while a person still awaits a result is treated as the worst possible failure. Two narrow exceptions exist (a bare emoji reaction may be a complete turn; a self-initiated routine wake with nothing to report may end silent). Delivery is defined strictly: plain assistant text is private scratchpad; only an explicit send-tool call reaches the user, so nothing "counts" until it is sent through that channel.

This is not text alone — it is enforced at runtime, three ways: a reminder appended to every incoming user message restating the reply contract; middleware that counts non-send tool calls since the last send and injects a corrective reminder when the agent stays silent too long or has produced a result it has not sent; and middleware that fires when a turn opened with tool calls but no opening send, telling the agent the user is watching silence and to acknowledge immediately. The reminders also carry the persona logic for why: unacknowledged tool activity looks to the user like a frozen app.

## What the current build does
The build's policy text has no turn-rhythm section at all. The per-turn reminder (`assembleTurnReminder` in `src/core/policy/assembler.ts`) is unconditional and state-based: a live todo ledger plus one fixed "Standing rules" block (`buildStandingRulesBlock` in `src/core/policy/prompts.ts`) whose six lines are all dispatch discipline — short turns, spawn vs parallel, steering, ledger reconciliation, workers never message the user. None of them states a reply-first duty, an ack-vs-delivery distinction, or a "never yield owing the user a result" rule. Delivery guidance exists only on wake turns (`buildWakeInstructionsBlock`): decide whether to speak, deliver what finished, silence is a valid outcome. The persona asserts immediate responsiveness once ("You stay responsive", prompts.ts line 81) but never turns it into an operation — no rule says when or how responsiveness is delivered on a user-visible turn. There is no runtime silence enforcement anywhere in the build.

## The deviation
The reference makes turn rhythm an essential part of the persona — a fixed contract (ack first, ack never pays the delivery debt, never finish a turn owing a result) backed by conditional runtime reminders that detect and correct silence. The build has the delivery half only, and only on wake turns; the ack-first half and any runtime backstop are absent. The build's per-turn reminder is unconditional rather than conditional, so it cannot apply pressure in proportion to how long the agent has gone quiet.

## Verdict: ADAPT
Under the authority stack this is prompt-asset territory governed by PRD §10, which lists no turn-rhythm asset — but the persona-side half (reply-first rule, ack ≠ delivery, never-end-owing-a-result, the private-text-vs-sent-message split) is pure system-prompt content the build can write as new text under §10's new-copy discipline; it belongs in the dispatcher system section and standing rules. The runtime half is limited by where the code can hook: reminder injection happens at host turn boundaries the addon does not own (ADR-0021's separate floating window over stock dsh), so the reference's middleware machinery should not be ported mechanically. The build's dispatcher is also wake-driven — the primary agent yields while workers run and is re-invoked on settles — so the reference's silence-reminder pressure is structurally different here: the real risks are opening a user-visible turn with silent tool work and closing a wake owing an undelivered result, both addressable in prompt text. Ask the human only if turn-rhythm rules should also govern peer turns (ticket 14 surface), where "user-visible" is murkier.
