# DD-220 — Auto-review classifier pipeline: instruction lists, decision shape, redaction
- **Area:** A28 approval & policy
- **Type:** deliberate-divergence
- **Date:** 2026-09-23

## What the reference does
The enforcement part of the reference's auto-review is a model-driven classifier, not a rule table. It is invoked through its own executor resource with a structured request carrying the tool call being judged, the parent conversation id, a risk target built on demand at call time, and conversation context loaded asynchronously (`reference material-NOT LICENSE SAFE DONT COPY-grok bot/source/host/runner/sand-auto-review-classifier-run.ts:22-50`). It makes a **single attempt** — the attempt cap is a constant set to 1 (`:15, :48`) — and returns a three-way decision union: plain allow; block with a reason and an optional proposed allow rule; or reject with a reason (`:17-20`). The block reason falls back to fixed copy when the model's reason is empty, and the proposed rule is only carried when non-empty after trimming (`:54-61`). Any non-success classifier outcome, and any thrown failure, returns reject (`:32, :51-52, :63-68`).

The classifier is steered by a persisted instruction object: an enabled flag plus two bounded lists (allow instructions, block instructions) with defaults of enabled and both lists empty (the reference tree's `source/shared/sand-auto-review-instructions.ts:3-4`). List normalization trims each entry, clamps it to 1000 characters, drops duplicates via a seen-set, and caps the list at 20 entries (`:1-2, :7-15`); a normalize function coerces partial/unknown input back to that shape, with the enabled flag defaulting true unless explicitly false (`:17-18`). So the steering surface is user-persisted policy text, size-bounded at both entry and list level.

Separately, the classifier path **redacts its own output before display**. A dedicated redaction module defines secret-value and secret-key patterns and an inline-secret scrubber (the reference tree's `source/shared/sand-auto-review-redact.ts:1-6`), and the scrubber is applied throughout the summary/display path — including over the instruction text, target URLs, and tool arguments that are composed into human-readable summaries (the reference tree's `source/host/runner/sand-auto-review-summaries.ts:4, :57, :129, :180-283`).

## What the current build does
No classifier layer exists, by explicit ruling. The review table file's own header states the table is session-scoped and deterministic over relay asks and worker dispatches — **NOT an LLM classifier layer**, recorded as the point where imitation of the reference stops under U-D — with no persistence beyond session scope, no settings-managed store, no silent allow outside the ask pathway, and no approve tool (`src/core/review-posture.ts:1-8`). The same file records the empty shipped default as deliberate (ruled 2026-09-19, ticket 69 Q1): a non-empty default, or a stored default loaded from Config or settings, would auto-answer access prompts without an explicit user act, contradicting ADR-0018 U-D and ADR-0011's "consent can never silently widen" — and any future non-empty default or Config seeder is a U-D amendment needing a human signature first (`src/core/review-posture.ts:136-149`).

The build's refusal path is **hard-coded text at the point where a spawn is allowed or refused**: a deny row refuses outright with the review table's deny detail under the `auto-review-refused` reason; a gated dispatch with no approval answerer refuses fail-closed with fixed copy; an approval outcome other than allowed-once refuses with fixed copy instructing the model to re-plan (`src/core/tools.ts:297-322`). The settings card edits exactly two schema fields — a boolean enable flag and a numeric access-request timeout — checked by an offline test against the config schema, and carries **no instruction-list field** of any kind (`src/client/settings-card-store.ts:194-214`).

## The deviation
The reference has a model-in-the-loop enforcement stage; the build has none, and the absence is ruled rather than unfinished. Concretely the build lacks: any classifier invocation path or its structured inputs (tool call, parent conversation, risk target, conversation context); any instruction store (enabled flag plus bounded allow/block lists); the entry/list bounding rules (trim, 1000-character clamp, dedupe, 20-entry cap); the three-way allow / block-with-reason-and-optional-proposed-rule / reject decision shape; any proposed-allow-rule surface; and any redaction pass over model-authored risk reasoning. The build's functional equivalent is a deterministic session-scoped review table feeding the code that decides whether to allow a spawn, whose refusal text is written by hand, not generated. The reference's classifier also takes an enforcement mode (shadow versus enforce) as an argument (the reference tree's `source/host/runner/sand-auto-review-classifier-run.ts:26, :44`) — that enforcement mode is covered by DD-216 and is not analysed again here.

**The one idea that stands alone.** One property of the reference's classifier is not about classification at all: it *redacts its own output before display*. That is a rule for controlling disclosure — the model's reasoning about a risk assessment is scrubbed of secret-shaped material before a human reads it — and it is conceptually independent of how the allow/block decision is made. No recorded ruling reaches this rule as such: U-D speaks to rule persistence and to who owns the permission controller, and the header of `src/core/review-posture.ts` names the classifier layer as where imitation stops. It is not currently actionable, though: with no classifier in the build there is no model-generated risk reasoning on the enforcement path to scrub — the gate's copy is authored by us and contains no model output — so a redaction pipeline would have nothing to act on here. It becomes worth re-examining only if a classifier is ever admitted. It is named here so that the idea is not lost inside a mechanism-level rejection, and it is not inflated beyond that.

Worth recording honestly: the build's hard-coded refusal text at that check is a legitimate design answer to the same problem, not a deficiency. It is deterministic (no model nondeterminism in the deny path), predictable to the user, auditable in source, and fails closed by default; it also carries no prompt-injection surface and no reliance on classifier availability. The reference's classifier buys nuance at the cost of a model dependency in the enforcement path; the build buys predictability at the cost of nuance. That trade is the one U-D already settled.

## Verdict: DO-NOT-INCORPORATE
ADR-0018 exception U-D rules that "always allow" approval rules are session-scoped and not persisted, with no settings-managed rule store and no dedicated local tool-permission controller (`docs/adr/0018-imitate-reference-in-entirety-exception-list.md:37`), and the build's own review-table header records the classifier layer itself as ruled out (`src/core/review-posture.ts:1-8`) — together these cover the classifier mechanism, its instruction store, and any settings-managed editor for it. The redaction idea can stand apart from the classifier; it is not reached by any recorded ruling, but with no classifier there is no model reasoning to redact, so there is nothing to adopt now. The verdict is therefore doubly grounded and does not need a human decision; if a classifier is ever proposed, the redaction rule should be reconsidered with it rather than separately.

## Incorporation notes
- **Where it would live:** nowhere today. A classifier would need a new core module beside the review table (`src/core/review-posture.ts`), a persisted instruction store, and a settings field surface (`src/client/settings-card-store.ts`) — the last two of which U-D forbids outright.
- **Constraints:** U-D (session-scoped, never persisted; no settings-managed rule store; no dedicated local tool-permission controller); ADR-0011 ("consent can never silently widen"); the review table's empty shipped default, its refusal to store patterns that contain wildcards, and the requirement that any non-empty default or Config seeder be a signed U-D amendment (`src/core/review-posture.ts:136-149`). The reference's rule that bounds instruction lists (entry clamp, dedupe, list cap) would be a prerequisite, not a refinement to add later, for any persisted user-authored policy text.
- **License note:** ADR-0018 B9 — re-derive independently; no verbatim copying from the reference tree.
- **Effort/risk:** L — a model-in-the-loop enforcement path plus persistence plus a settings surface, built against an explicit exception; the risk is policy drift (auto-answers arriving without an explicit user act) plus introducing nondeterminism and an injection surface where the build now has deterministic fail-closed text.
- **Key reference anchors:** the reference tree's `source/host/runner/sand-auto-review-classifier-run.ts:15-68` (single attempt, decision union, request shape, reject-on-failure); the reference tree's `source/shared/sand-auto-review-instructions.ts:1-19` (enabled flag, bounded lists, clamp/dedupe/cap, normalization); the reference tree's `source/shared/sand-auto-review-redact.ts:1-6` (secret patterns and inline scrubber); the reference tree's `source/host/runner/sand-auto-review-summaries.ts:4, :57, :129, :180-283` (redaction applied along the display path).
