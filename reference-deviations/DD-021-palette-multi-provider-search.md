# DD-021 — Palette fuzzy multi-provider search vs no search surface
- **Area:** command palette (A3)
- **Type:** missing-feature
- **Date:** 2026-09-23

## What the reference does
The reference implements a client-side command-palette search pipeline. A normalization layer folds input with Unicode NFKD, strips diacritics/combining marks, lowercases, and splits on non-alphanumerics into search tokens (`command-palette-model.ts:49-70`). A pure fuzzy scorer walks the query against candidate strings, awarding bonuses for word/camel-case boundaries and contiguous runs, rejecting matches whose span exceeds roughly three times the query length, and penalizing late and long matches (`command-palette-model.ts:47,72-96`); entries are scored over label plus keywords (`command-palette-model.ts:98-132`). Results are filtered by tab (All/Messages/Agents/Groups/Files/Links/Routines/Actions, `command-palette-model.ts:107-115`), and hidden agents are searchable but always ranked after visible results (`command-palette-model.ts:162-171`). The scored entries are fed by async providers: recent messages via the coordinator's agent-search endpoint behind a 150 ms debounce (`command-palette-message-provider.ts:6,36,149`); files via the media-search endpoint with a 50-result cap (`command-palette-search-provider.ts:7,52,161`); link titles/favicons via a desktop-bridge metadata call (`command-palette-link-provider.ts:37,138`); and routines via an all-automations listing wrapped in a loading/ready/empty/failed snapshot state machine with recency ordering by last-run time (`command-palette-provider.ts:17-20,33,51,79,127-137`).

## What the current build does
Nothing comparable. A case-insensitive search of `src/` and `client/` for any palette or provider identifier (search endpoints, bridge metadata, automations listing, fuzzy scoring) returns zero matches: the build has no command-palette search surface, no fuzzy scorer, no tab filter, and no client-side search UI of any kind — the client surface is conversation rendering only.

## The deviation
The reference turns its command palette into a multi-provider search engine over agents, messages, files, links, and routines; the build omits the entire capability rather than implementing a weaker version of it. This is an absence of a surface, not a behavioral difference inside an existing one.

## Verdict: ADAPT
Under the repo's ruling order, the PRD's scope and the A3 surface definition govern, and the palette's fate is not settled here: this deviation depends on how DD-019 resolves the palette question (the related deviations are not yet numbered), and full parity is impossible because three of the four providers depend on capabilities the build does not have — routines/automations, desktop-bridge link metadata, and the coordinator media/agent search endpoints (providers themselves absent; not yet filed as numbered deviations, content-search). The part that carries over without a licensing problem is the pure normalization/tokenization/scoring code plus the snapshot-state pattern. That part could be written again independently behind the build's own boundary between core and client, if DD-019 adds a palette at all; wiring the routine and link providers should wait until their underlying features exist or are explicitly ruled out of scope. Re-derive everything per ADR-0018 B9 — no copying from the reference tree.

## Incorporation notes
- **Where it would live:** a search/palette module under `src/` (core-side scorer as a pure unit; provider interfaces at the boundary that already exists between core and adapter), surfaced through `client/` only per what DD-019 decides.
- **Constraints:** scorer must stay a pure function that can be tested offline (repo offline-test rule); async providers need the build's own cancellation/debounce patterns; routines and links providers are blocked on features that do not exist in the build (not yet filed as numbered deviations); hidden-agent ranking rules must be re-derived against the dispatcher's own agent model, not transplanted.

- **Effort/risk:** M — the scoring/tokenization core is small and pure, but provider wiring spans coordinator surfaces the build lacks, so scope can grow into features the PRD may exclude; wait for DD-019's decision first.
