# DD-161 — Resume / self-fork / interrupt vs the build's terminal-work stance
- **Area:** A19 tool surface
- **Type:** behavior-delta
- **Date:** 2026-09-23

## What the reference does
The reference's delegation tool exposes, alongside ordinary start-a-subagent use, three additional capabilities. First, it can **resume an already-started subagent** — the caller points at prior subagent work and continues it rather than starting fresh. Second, a related **self-fork** capability lets the calling agent continue from itself; the name describes the role here, not a literal identifier. Third, the reference supports an **interrupt** capability (a mid-flight signal into a running subagent), and a **foreground** mode in which the run is not backgrounded at all but kept in-line with the caller's turn. The relevant reference source is the task module under `reference material-NOT LICENSE SAFE DONT COPY-grok bot/source/packages/agent/tools/task.ts`, around lines 361–365: that is where the resume-path and self-fork option and the foreground/background inclusion decision are derived from the host capability flags before the tool's parameter schema is built (lines 361–364 feed the schema builder at 366–383). The same module's completion and schema siblings (`task-subagent-completion.ts`, `task-tool-schema.ts`) are where these options land.

## What the current build does
The build's work is **terminal by construction**: once a worker settles, its task is finished, and there is no resume path. `src/core/policy/prompts.ts` states this position and its consequences directly — the spawn tool description tells the dispatcher that the worker's final response "arrives later — do not wait or poll" (line 29), the steer tool is explicitly *only* for "a worker that is still running" and is "Refused if the worker is not running" (line 33), and the stop tool tells the model that after a stop "any later result from it is dropped" (line 35). There is no tool that re-opens a settled worker. Instead the build reconstructs **durability** from persisted state on restart: `src/core/multitask.ts` `rebuildFromDurability` restores terminal rows and converts a live-at-crash worker into an honest unknown-state entry, and its own comment says plainly that "Neither implementation resumes or replays a worker" and that "our non-use of it is a core design decision, not an oversight" (lines 856–864). The worker contract in `src/worker/prompt.ts` is written as a self-contained, single-shot brief (the task is the child's first user turn, lines 12–14) — nothing in it anticipates being continued. Steer, not resume, is the build's mid-flight intervention: a correction goes to the running worker ("Correction → steer the running worker; do not clone", `prompts.ts` line 116) and is refused once the worker is not running.
## The deviation
The reference treats a delegation's session as a resource that can be re-entered (resume, self-fork) and interrupted; the build treats it as **one-shot and terminal**. The build's stance is not an oversight and should not be presented as a gap: it follows from the recorded decision **ADR-0012** (`docs/adr/0012-restart-replays-durability-never-work-draft-nonhuman-approved.md`), whose decision is that a dispatcher on (re)start "replays durable records only — it never re-runs a worker, re-dispatches work, or invents state the markers do not carry," and whose Consequences state the restart path is "bounded by construction: one notice, one redrive pass, no re-execution." Resume would give completed work a second life, which is exactly what ADR-0012's durability model (ADR-0006's minimum-to-reconstruct) exists to prevent. The interrupt piece only *partly* overlaps the build's steer capability — steer delivers a correction and preserves context, an interrupt is a harder signal — and the foreground piece is a host-side run-mode concern that the build does not own (its workers are background by design). So the three pieces should not be met with one verdict; the plan addresses each piece separately below.

## Verdict: DO-NOT-INCORPORATE
ADR-0012 is a recorded ruling and it is decisive for the resume path: restart replays durability, never work, so a resume capability would contradict the durable model the build already ships. ADR-0010 (dispatcher presence is a projection of core state, never an optimistic guess) bears on the same point — a re-opened worker would be invented state rather than a projection of recorded state. For interrupt and foreground mode the picture is different and should be said so rather than lumped in: interrupt partly overlaps the existing steer tool (which the build already offers for live workers and refuses for settled ones), and foreground mode is a host-side concern outside the build's own surface. ADR-0018 (imitate the reference except the enumerated exceptions) is the master rule, so any of these three would need a written, enumerated exception before implementation; no recorded ruling grants one for resume, and none is claimed for interrupt or foreground here. Note that ADR-0012 is a *draft* record (not yet approved by a human; it records the decision as shipped), so a human could reverse it — but until then it is the recorded decision and this deviation is a deliberate divergence, not an unruled area.

## Incorporation notes
- **Where it would live:** The resume/self-fork path would need a new capability in `src/core/multitask.ts` (worker lifecycle and roster) plus a new dispatcher tool in `src/core/policy/prompts.ts`; the interrupt piece would extend the existing steer path (`STEER_WORKER_TOOL`, `prompts.ts` lines 32–33); the foreground piece would be an adapter concern, not core. None of it is adopted here.
- **Constraints:** ADR-0012 forbids re-running or re-dispatching work on restart; ADR-0006 fixes durability at the minimum needed to rebuild state, so a resumed worker would need state the markers do not carry. ADR-0010 forbids optimistic presence — any resumed worker must appear only if core state can honestly project it. ADR-0018 requires a written enumerated exception before imitating the reference on any of these three.
- **License note:** ADR-0018 B9 — re-derive independently; no verbatim copying from the reference tree.
- **Effort/risk:** L for resume/self-fork (touches the durable model, the roster, the tool surface, and the policy text at once, and re-opens ADR-0012); M for interrupt (partial overlap with steer); S for foreground mode (host-side and arguably out of the build's scope).
- **Key reference anchors:** `reference material-NOT LICENSE SAFE DONT COPY-grok bot/source/packages/agent/tools/task.ts` lines 361–365 (resume-path/self-fork and foreground inclusion derived from host capability flags, feeding the schema builder at 366–383); sibling modules `task-tool-schema.ts` and `task-subagent-completion.ts` in the same directory.
