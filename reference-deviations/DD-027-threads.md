# DD-027 — Threads (affordance, counts, open/summary lifecycle) vs none
- **Area:** transcript delivery states (A4) / message cards (A10)
- **Type:** missing-feature (ruled exception)
- **Date:** 2026-09-23

## What the reference does
The reference conversation surface has a complete thread presentation layer spanning cards and the transcript. On a message that starts a thread, a button affordance renders whenever there is a summary with a positive whole-number reply count; if the root id is empty, or the count is missing, malformed, or not positive, it renders nothing (`cards/transcript-card/thread-affordance.tsx:18-33`). The button's accessible name pairs an open-the-thread action with the reply count, and it shows a visible caption stating the count in singular/plural reply wording (`thread-affordance.tsx:14-16`, count span at line 30).

Counts are not tracked locally: a map from root entry id to reply count, delivered one page at a time, is matched against the entry ids currently present in the transcript window. Unknown roots and malformed counts are dropped silently, so only valid roots inside the window show a count (`thread-summary-controller.ts:19-30`). A scoped controller (account slot + agent id, generation counter) indexes summaries and entry ids with replace/prepend/append merge methods, and its navigation method resolves a target id to either an in-window scroll callback or an out-of-window open-thread callback, then restores focus (`thread-summary-controller.ts:32-64, 137-149`). A separate loader state machine (idle / unavailable / loading / ready / empty / failed) fetches a thread's entries by agent id plus root id through a structural transport boundary, de-duplicates concurrent loads of the same root, and resets on scope change or dispose (`thread-loader.ts:9-47, 76-161`). The transcript wires it together: an optional start-thread callback prop, a thread action hidden once already inside a thread view, rendering of the affordance when both a summary and an open-thread handler are present, and an in-thread root-id marker for the in-thread case (`workspace/transcript.tsx:46, 155, 208, 217, 758`).

## What the current build does
Nothing. A search of `src/` finds the word "thread" only in comments that explicitly record the concept as deliberately absent under the ADR-0018 exception: a forward-compatibility conversation-slot field that is never surfaced as threading (`src/core/peer-types.ts:24-26`), a policy note that a threading concept is excluded (`src/core/policy/assembler.ts:220`), and a tool-layer note that threading is excluded (`src/core/tools.ts:241`). There is no thread state in the store, no reply counts in the feed, no pane or card affordance, and no open/summary lifecycle.

## The deviation
The reference presents per-message thread affordances on card/message surfaces. The reply count is taken from a page of counts and matched against the visible transcript window, and entries that do not match are simply not drawn. A scoped open/summary lifecycle handles opening and navigating (controller navigation plus a loader state machine over a thread transport). The build has no thread concept anywhere in store, feed, or pane — an intentional absence recorded as ADR-0018 exception U-B, which excludes threads and replies from imitation, and noted in the build's own comments. The adjacent replies surface (reply pill and reply pipeline) is a separate deviation covered by DD-026; this file covers only the thread affordance, counts, and open/summary lifecycle.

## Verdict: DO-NOT-INCORPORATE
ADR-0018 — the human-ruled top-level decision — lists exception U-B as excluding threads/replies among the rich chat ergonomics, so the absence is a recorded ruling, not an oversight, and the build's comments cite it deliberately. Under the repo's ruling order, an accepted human ruling settles the question; the PRD sits below accepted ADRs and does not reopen it. The reply-pipeline aspects neighboring this surface belong to DD-026 and follow their own ruling there. This file stands as the inventory of what would return if the human ever reverses U-B for threads; until then no incorporation work is authorized.
