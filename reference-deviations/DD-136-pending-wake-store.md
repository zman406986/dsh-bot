# DD-136 — Durable pending-wake store & boot re-arm vs marker rebuild
- **Area:** agent runner / turn execution (A16)
- **Type:** deliberate-divergence (recorded resolution)
- **Date:** 2026-09-23

## What the reference does
Background wakes are made durable at the moment they are set up. A small JSON-file store (`sand-pending-wake-store.ts`) keeps one marker per outstanding wake, keyed by parent agent, wake kind, and work id, with a timestamp; writes go through a temp-file-plus-rename so a crash mid-write cannot corrupt the list, and markers are upserted, cleared individually, cleared per agent, or cleared wholesale as watches start and settle. Three wake kinds participate: cloud-agent watches, background shells, and subagents. On boot a re-arm pass (`pending-wake-rearm.ts`) first prunes markers older than a 48-hour staleness limit (constant at `pending-wake-rearm.ts:6`), then walks the survivors: agents known to be gone are skipped and the skip is recorded; a cloud-agent marker re-arms the cloud watch if not already pending; a shell marker re-arms the background-shell watch, with a special path for shells interrupted by a session recreate that instead delivers an interrupted-shell notice; and a subagent marker is never re-watched — since the child's in-process run did not survive, the parent is revived with a synthetic error completion saying a host restart interrupted the background task before its result could be delivered (paraphrased; the lost-subagent-wake parent revival, `pending-wake-rearm.ts:233-263`), pointing the user at the child transcript and a fresh dispatch. Failed re-arm attempts save their marker again for a later pass, and every outcome is recorded.

## What the current build does
Restart recovery rides the durable task markers the dispatcher already keeps, not a separate pending-wake store. At session activation an async chain (`rebuildAndNotice`, `src/plugin.ts:584-649`) rebuilds terminal rows from the marker store, publishes the first roster snapshot, then — per ticket 57 / register D-4 — routes an honest restart notice through the wake mechanism so recovery actually opens a turn without the user speaking first, and — per ticket 58 / register D-5 — runs a bounded pass that resends results that landed before the restart but were never delivered, which can escalate an exhausted delivery duty to a terminal lost state. Workers found live at crash time are not fabricated as settled: the restart notice states them as UNKNOWN and holds their stream keys with release instructions (ticket 59, `src/adapter/restart-notice.ts`). Per ADR-0018 exception item 8 (C15, `docs/adr/0018-imitate-reference-in-entirety-exception-list.md:30`) only one wake kind exists here — dispatched workers — so this machinery covers exactly that kind and nothing else.

## The deviation
The reference saves the wake intent itself, durably, when the wake is set up, and re-establishes the underlying watches on boot — including synthesizing terminal completions for subagent work that cannot be watched again. The build persists settled/terminal markers and resends undelivered results at activation, and holds unknown-state workers honestly, but it has no durable record of an in-flight wake written when the worker is dispatched, so a crash in the window between dispatch and settle leaves only a report that the worker's state is unknown, never a re-wake. The build's equivalent is functional for its single wake kind; for the reference's cloud-agent and background-shell watch kinds the build has no counterpart at all, so the pending-wake store is empty of content there because of C15 rather than missing.

## Verdict: DO-NOT-INCORPORATE
This is a ruled divergence with the equivalent already recorded: D-4 (removed 2026-09-18, ticket 57) fixed the recovery mechanism to a genuine wake and D-5 (removed 2026-09-18, ticket 58) added the bounded boot-time resend of undelivered results — the register records the D-5 limit as mirroring the reference with no new divergence logged, and the D-5 design note (`docs/research/dsh-core-loop-deviations.md:47`) explicitly warns against blind copying of reference limits. ADR-0018's C15 rules out the other wake kinds outright, so a per-watch durable store with boot re-arm has no legal home here, and the human-ruled master ADR plus the PRD scope bind the same way. The one genuinely open piece — saving the wake intent at dispatch time so a crash between dispatch and first settle could re-wake instead of only reporting an unknown state — is an extension of the closed D-4/D-5 equivalent, not a gap this file can close: it would need fresh ticket-level evidence and a ruling, and it belongs with the restart-semantics writeup (DD number pending, restart).
