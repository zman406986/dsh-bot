# DD-181 — Agent-store sync and box transfer
- **Area:** A21 storage
- **Type:** missing-feature
- **Date:** 2026-09-23

## What the reference does
The reference ships two related replication subsystems plus an agent-duplication module. An agent-store sync replicates per-agent store files to object storage: a local index records each file's sync direction, hash, and last-seen etag, with an explicit tombstoned state and a stored tombstone etag so deletions propagate; a small normalization layer handles quoted object-store etags; a round scheduler decides whether to run a full pass or a path-scoped pass, and lets a full pass yield to a path pass; and a concurrent-write conflict handler keeps the losing writer's content when a canonical write loses a race. A separate box-store sync (in the reference, "box" means a machine) packs a machine's whole store bundle into large compressed pack objects described by a versioned pack index and a retired-packs list, verifies members by size and hash on both pack and extract, downloads/copies-in from a manifest, stages snapshots with free-disk probing, and restores a machine from the packs — a step the reference calls "hydration" — guarded by a durable marker that the restore finished and a check for whether the machine is fully restored. Separately, an agent-clone module duplicates an agent's directory: it checkpoints and copies the agent's store file, rewrites profile/settings/avatar/automation identity for the copy, and rolls the target back on failure.

## What the current build does
Absent. The build has no remote store replication, no tombstones, no packing or restore pipeline, and no agent clone. Its persistence is the local marker durability layer: `src/core/durability.ts` defines the minimum-to-reconstruct worker marker (ADR-0006), and `src/adapter/durable-marker.ts` writes those markers into a dsh storage-domain table — no second database, no transcript copy, nothing off-host. A search of `src/` and `client/` for tombstone, etag, object-storage, and clone terms returns no real matches (only substring false positives on an unrelated getter name).

## The deviation
The reference's sync and clone subsystems exist to make a user's per-agent stores portable across machines — coherent in a product where a user's agents follow them across devices, with the account and device model that implies. The build is a single-host Cordis plugin with no account or device model: ADR-0018 exception U-A removes privacy/account gates, and the PRD is local-first (goal 8) with remote-sandbox/remote-desktop parity as a non-goal (§2). With no multi-device premise there is nothing to replicate, and ADR-0018 exception A5 ("persistence stays in dsh's session/job store; no second database") rejects the store-under-replication model outright. The clone module maps to two further exceptions: C13 (no persistent agent identities) and U-G (no runtime create/clone of agents).

## Verdict: DO-NOT-INCORPORATE
Recorded rulings cover this deviation, so no new judgment is needed: ADR-0018 A5 rules out a second database (hence any store to replicate or pack), U-A removes account/privacy gates, C13 removes persistent agent identities, and U-G removes runtime agent cloning; ADR-0006 (accepted) fixes the build's persistence to the local minimum-to-reconstruct marker in dsh's own store. The multi-device, account-anchored premise that makes the reference's sync coherent is absent from this product (PRD §2 goal 8 local-first; non-goals exclude remote sandbox / remote desktop parity), so the subsystem would have nothing to serve here. Nothing on the authority stack suggests a re-open; only a future human adoption of a multi-device story — which would re-open A5 — could change this.
