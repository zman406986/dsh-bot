# DD-095 — Per-agent presence vocabulary vs session-aggregate presence
- **Area:** sidebar / roster / agent management (A11)
- **Type:** deliberate-divergence (the design deliberately reports at session level, not per agent)
- **Date:** 2026-09-23

## What the reference does

Each sidebar row speaks per-agent: the row computes its own marker (a blocked/unread pair rendered as two short marker labels, one for needs-attention and one for unread activity), a status dot with five distinct states (a five-value status vocabulary: idle, needs-attention, offline, error, informational), and a running indicator that changes shape depending on whether the agent currently has a named activity (plain running pulse vs a named-activity ring). Rows also carry a relative updated time in compact now/minutes/hours/days form, and the hover preview ranks detail as draft first, then waiting reason, then the last message excerpt. Anchors: the sidebar agent-status calculator and the five-state dot record in `the reference tree's frontend/src/recovered/features/conversation/workspace/sidebar-agent-status.ts`; the row item component in `sidebar.tsx`; the hover card in `sidebar-agent-preview-header.tsx`.

## What the current build does

Presence is aggregated per dispatcher session, not per worker. `describePresence` (`src/client/shell-store.ts`) folds the mirror snapshot's workers into three counters — `working` / `needsYou` / `finished` — reusing the roster panel's own grouping rule, so the sidebar chips and the panel sections can never disagree. One waiting marker per session (`describeWaiting`): the first blocked row in roster order wins, else the marker for a result that has landed but not been delivered. `describePresenceDot` (`src/client/shell.tsx`) collapses the session to one of five dot states (`working` / `needs-you` / `finished` / `idle` / `unavailable`), where `unavailable` is the state that says plainly that there is no live data. The hover preview (`describeRowPreview`) ranks the waiting marker first, then the recent-result excerpt; the reference's draft-first tier is skipped entirely because per-agent drafts are excluded from the data model — a recorded gap (ADR-0018 U-B) that is never faked. Sidebar rows carry no relative updated time; the roster panel rows show start time plus elapsed.

## The deviation

Same surface, inverted granularity: the reference answers "what is this agent doing" on every row, while the build answers "what is this session's workers doing" in aggregate, because the dispatcher session owns the sidebar row and its workers are only visible through the mirror snapshot. The ticket-79 comments in `shell.tsx`/`shell-store.ts` explicitly record this move to session granularity (moving the ticket-27/28 presence semantics onto the sidebar, ADR-0020 slice 3). The vocabulary also differs in kind: the reference dot lists per-agent runtime states (offline, error, and informational among them), while the build dot lists session-level combined states plus one that says plainly that data is unavailable. Two reference refinements have no session-level equivalent today — the relative updated time on each row, and the draft-first preview tier (the draft tier cannot exist at session granularity since drafts are per-agent and excluded per ADR-0018 U-B).

## Verdict: ADAPT

The granularity inversion is the recorded model, not a gap: ticket 79's comments in the build files record the move to session-level aggregation, and ADR-0018 U-B already rules per-agent drafts out of scope, so wholesale re-introduction of per-row agent states would reopen settled decisions. What adapts cleanly is vocabulary detail that survives aggregation: richer role labeling for the session dot mapped onto the existing working/needs-you/finished grouping, an unread/blocked-style marker treatment for the session's waiting state, and a relative updated time derived from the mirror snapshot's latest activity. The draft preview tier stays a recorded gap — reviving it requires a human ruling against ADR-0018 U-B, not a sidebar patch.
