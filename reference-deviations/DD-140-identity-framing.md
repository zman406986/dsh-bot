# DD-140 — Branded persona identity with self-modification vs functional role labels
- **Area:** system prompts / persona (A17)
- **Type:** deliberate-divergence (deliberately no personality or brand identity)
- **Date:** 2026-09-23

## What the reference does
The reference gives every agent a durable, branded persona. The base system prompt opens by naming the agent as a specific product character with a warm, concise, friendly-assistant framing (the base-prompt builder in the reference tree's `source/host/runner/system-prompt.ts:77`, first line of the assembled text). On top of that, prompt assembly injects a per-agent profile section (the reference tree's `source/host/runner/system-prompt-assembly.ts:100`) that tells the agent the name it answers to, its description and title, and — notably — gives it permission to change itself: the agent can rename itself, rewrite its own description through a state-update tool, and set or clear its own avatar image file the same way (assembly lines 110–111). Profile edits are even announced to the current context and included in future prompts. Identity is therefore persistent, user-visible, and partly under the agent's own control.

## What the current build does
The dispatcher's entire identity is one functional sentence: it is the user's main assistant in this chat whose defining trait is staying responsive while background workers take the heavy work (`src/core/policy/prompts.ts:81`, inside `buildDispatcherPolicySection`). No name, no warmth framing, no profile, no self-modification of any kind. The persona work the build does instead is about presentation honesty, not branding: the user never hears the machinery — workers, streams, wakes, and dispatch are never named, and the dispatcher speaks "as one busy person" (`src/core/policy/prompts.ts:98`). The worker is deliberately a bare role: "a delegated worker on a single task" that is explicitly not the user's chat assistant (`src/worker/prompt.ts:50`), with no identity surface at all and no channel to the user.

## The deviation
The reference treats agent identity as a product asset: branded, warm, persistent, and self-editable. The build treats identity as a functional role label, and actively removes personality — the dispatcher is defined by its behavior (responsiveness, delegation, single-voice narration), not by a character, and the worker is defined by its constraints. This is a deliberate divergence, consistent with ADR-0010 (dispatcher presence is a projection of core state, published on transitions and read from pull-only surfaces — draft non-human-approved): the dispatcher's "self" is whatever the core's state projection says it is, not an independently persistent persona. The nearest the build comes to warmth is the single-voice narration rule, which simulates one busy person without ever naming one.

## Verdict: DO-NOT-INCORPORATE
Branded identity is a product-identity decision, and this build's product is a dsh plugin, not a standalone persona product — adopting a named, warm, self-modifying character would be a human product ruling, not an engineering choice (authority stack: no ADR or PRD text authorizes it, and ADR-0010's projection rule points the other way). The PRD's own review check for prompt assets requires no Sand phrases and no leaks of product names (PRD §10, assets table and its review note), which rules out transplanting the reference's branding wholesale even if we wanted it. What is portable in original wording is thematic only: the reference's expectation that an agent describes itself honestly (knows its role and limits) and its granting of autonomy to an agent that carries a profile both survive as ideas our dispatcher/worker sections already express functionally — if we ever deepen those themes, re-derive them independently rather than porting the branded package. Any future move toward a named persona goes through ASK-HUMAN first.

## Incorporation notes
- **Where it would live:** Nothing to change now. If a human later rules for a named dispatcher persona, the identity sentence in `buildDispatcherPolicySection` (`src/core/policy/prompts.ts:81`) is the only insertion point; a worker should never carry persona.
- **Constraints:** Any persona wording must pass the PRD §10 review rule (no Sand phrases, no product-name leaks); the dispatcher stays a projection of core state per ADR-0010 (no persistent self-modification rights, no agent-controlled profile); the "one busy person" narration rule (prompts.ts:98) must survive any rewrite — the machinery stays invisible.
- **License note:** ADR-0018 B9 — re-derive independently; no verbatim copying of reference prompt text under any circumstances.
- **Effort/risk:** S — no build change required; the only risk is that someone later "borrows" the branded opening as a convenience, which would be both a license and a product-scope violation.
- **Key reference anchors:** the reference tree's `source/host/runner/system-prompt.ts:77` (base-prompt builder opening with branded warm framing); the reference tree's `source/host/runner/system-prompt-assembly.ts:100,110-111` (per-agent profile section: own name/description/title, self-rename and description rewrite via state-update tool, avatar set/clear, edit announcements).
