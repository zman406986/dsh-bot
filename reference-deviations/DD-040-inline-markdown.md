# DD-040 — Inline markdown formatting & autolinks vs literal text
- **Area:** rich rendering (A5)
- **Type:** missing-feature
- **Date:** 2026-09-23

## What the reference does
The reference transcript renders assistant text with inline formatting. A single inline-render function (in the reference tree's `frontend/src/recovered/features/conversation/workspace/transcript.tsx`, defined at line 247) walks the text with one combined regex and emits React nodes as it goes: bold, italic, strikethrough, and inline code markers become `strong`/`em`/`s`/`code` elements (the first three recurse into the same renderer, so nesting survives), inline math spans become a math widget, and links appear two ways — `[label](url)` and bare `http(s)` URLs. Bare URLs are autolinked: trailing punctuation runs (closing brackets, commas, periods, and the like) are removed from the end of the match and re-emitted as literal text after the anchor, and only http/https targets become anchors (anything else falls back to literal text). A link-normalizing helper imported from the reference's URL-card module (used at line 482) normalizes hrefs for the labeled-link path. Every anchor gets `rel="noopener noreferrer"` and opens in a new tab. The same inline renderer feeds paragraphs, blockquotes, headings, list items, and table cells (lines 399–416), so all assistant prose gets it.

## What the current build does
The build's conversation pane (`src/client/conversation.tsx`, ticket 80, part 4 of ADR-0020's wrapper plan) renders each turn's text as one plain span with `white-space: pre-wrap` (line 356, class styled at line 74). There is no markdown scanner anywhere in the build client: no bold/italic/strike/code parsing, no autolink pass, and no anchor element is ever created — asterisks, underscores, tildes, backticks, and raw URLs all display exactly as the model emitted them. The pane's own header records the choice as deliberate scoping: it calls the display "text-only" and cites U-B as excluding rich ergonomics. A search of `src/` and `client/` finds none of the reference's inline-renderer or link-normalizing symbols.

## The deviation
Assistant turns that read as formatted prose in the reference render as raw markup characters in the build. This is a missing feature in two ways: (1) cosmetic — bold/italic/strike/inline-code are silently shown as literal characters, degrading readability of ordinary model output; (2) functional — URLs in assistant messages are not clickable, so the user must manually copy a link out of the pane to follow it. The functional gap is a real capability gap, not a styling difference.

## Verdict: INCORPORATE
ADR-0018 is the top human ruling: imitate the reference in its entirety with a closed exception list, and nothing on that list names inline markdown or autolinking — U-B's list covers optional extras (find-in-chat, threads, reactions, drafts, attachment viewers, URL *cards*), not the formatting of transcript text itself, and ADR-0020's area-9 exclusion row (rich chat ergonomics) copies U-B's wording verbatim rather than extending it. Under the authority stack, the pane's ticket-level "text-only under U-B" interpretation cannot stretch a closed ADR list, so the default resolves toward the reference; the clickable-link part makes the case stronger still, since a URL the user cannot open is a functional gap distinct from cosmetic bold/italic. Incorporation must be an independent re-derivation (ADR-0018 B9), and if the human intends inline formatting to be covered by U-B's "rich ergonomics" exclusion, that extension is theirs to rule — the deviation file records which way the evidence points so nothing is silently picked.
