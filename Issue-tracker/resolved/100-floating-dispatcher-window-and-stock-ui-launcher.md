**DOM technique (this ticket's evidence, per ADR-0021's open question): REACT PORTAL, not slot composition.** The window `createPortal`s into a module-owned `document.body`-level container. Evidence: (1) the overlay seam has NO geometry/anchor/positioning API — entries are "plain React roots inside a frame-wide absolute layer" that "position and size themselves with their own DOM" (`docs/research/dsh-capsule-seams.md` Seam 1), and stacking inside that layer is sibling DOM order — a viewport-anchored window that must stand above ALL chrome is brittle there, while a body-level container escapes the app frame's stacking/containing contexts; (2) a second always-registered overlay entry was rejected on the recorded one-entry-per-surface posture (ADR-0013) and because register/unregister-per-toggle churns host registry lifecycle for what is view state; (3) theme survives the portal because the `--dsw-alias-*` tokens are defined on `body` and every body descendant inherits them (`docs/research/dsh-plugin-ui-patterns.md` Finding 5, ticket 49); (4) `react-dom` is a platform seed word the loader's `require` resolves (`src/client/wrapper.ts`, ticket 20 Finding 4) — no new host seam; the build's `external` list already carried it, and the scaffold bundle pin was re-based to EXPECT `require("react-dom")`.

**Crash isolation (the new guarantee, recorded):** two layers. Host layer (evidence, no code): every slot entry renders inside dsh's per-entry `SlotErrorBoundary` ("one registrant crashing … must not take down siblings", ui-renderer `lib/client.js:511-532`) and for a `list` slot a crash reports `abdicate: true` — only the crashing entry is retired, siblings and the app stand (`docs/research/dsh-capsule-seams.md` Seam 1); under the additive posture stock dsh was never shadowed, so any crash of our entry leaves it standing. Our layer (strictly stronger, because the ticket requires the CHIP to survive a window crash and the portal keeps the window in the chip entry's React subtree): `DispatcherWindowBoundary` wraps the hosted shell INSIDE the window below the portal — a shell crash renders the honest `launcher.window.failed` line with working chrome; the chip, stock dsh, and the window itself survive; close + reopen mounts a fresh boundary (keyed by `openEpoch`) and recovers. Pinned by a rendered jsdom test with a genuinely throwing child, plus a structural pin that the boundary sits in the body below the chrome.
