# A spawned dispatcher's mark rides the existing `sessionKind` projection, and one header seat renders it

**Status:** draft (non-human-approved) — **agent ruling 2026-10-28**, made under the owner's full-rein grant dated 2026-10-28 and **explicitly subject to human reversal**. Pending human sign-off; it becomes accepted only on the owner's signature. Nothing in this draft retires an existing decision.

**Approval:** non-human — agent-drafted, pending human sign-off.

**Numbering:** 0031, the first free number at filing (2026-10-28; the highest in `docs/adr/` was 0030). Checked against every local branch and worktree, so the number collides with nothing in flight. Our ADRs live only in `docs/adr/`; upstream racoons numbering is a separate series and is not touched.

**Relates to:** ADR-0024 rider (2026-10-18) and its addendum — the rider's seat enumeration stands, and this draft extends it by exactly one seat; ADR-0024's rider **item 1** is the clause read here; ADR-0027 (the `sessionKind` projection is the identity source); ADR-0018 (imitate the host — no fork); ADR-0025 (mitosis); ADR-0006/A5 (no second database).

## Decision

1. **The spawned-dispatcher mark rides the existing `sessionKind` projection key.** No new projection key is added. `sessionKind` is already registered by the adapter, already durable, and already the identity source the sidebar glyph keys on (ADR-0027's settled identity rule; ticket 123's shipped read path). A spawned dispatcher reuses it rather than introducing a parallel channel.
2. **The host-side projection unit consults the adapter's dispatcher-mark mirror.** `spawnDispatcher` **seeds** the mirror with the reserved child id **before** `startActivation`, because the projection unit's `init` runs at `session/created` inside that call while the durable `dispatcher_sessions` row is only written after the spawn resolves. The seed is provisional: `finally` **deletes it when the spawn fails** (or when the host minted its own id), so a failed spawn leaves no phantom mark for the peer fence to read. The probe is late-bound — the unit is registered before the host object exists, so it reads a mutable ref rather than capturing a host instance. Fail-closed: a missing probe, an unreadable header, or a throwing probe all fold as "not a dispatcher", never as an error on the create path.
3. **The client renders the dispatcher glyph for a spawned dispatcher from `projectionValues.sessionKind`**, in that child's own **conversation header actions** slot. The read is direct — no `origin` gate — because the seated session *is* `origin: 'subagent'`; `resolveSessionKind` keeps its origin-first order untouched and is not used at this seat.
4. **Exactly one seat is added, and it is licensed narrowly.** ADR-0024's rider enumerated the seats exhaustively ("exactly one additional additive registration, and it is this one … no other slot is licensed by this rider"). This ruling extends that list by one: `conversation.session.header.actions`, additive in the list band above every stock occupant, **for the dispatcher mark only, on subagent-origin children**. The worker mark stays declined in every seat (ticket 123's 2026-10-22 disposition is unchanged).
5. **Boundaries that bind this decision.** No new projection key, no new host channel, no preset duplication at spawn, and no fork of stock dsh. The rider's "no new host channel is licensed either" sentence still binds; what this draft corrects is the rider's **premise about how identity reaches the client**, not its prohibition.
6. **Reversal is a single seam.** Undoing this ruling deletes one client registration and one `init` source (the mirror probe); the projection key, its fold, the adapter's mirror, and every other seat are unaffected.

## Context

**The ticket.** [Ticket 140](../../Issue-tracker/resolved/140-spawned-dispatcher-glyph-parity.md) records the owner's 2026-10-22 ruling — "spawned dispatchers should get same glyph as user spawned dispatcher, doesn't matter if user or a dispatcher initiated the command" — and the two blockers that stopped it: no identity, and no seat.

**Why a spawned dispatcher read as a worker.** It is a host subagent child, so its durable header carries `origin: 'subagent'` and `delegationDepth`, identical to a worker's. `resolveSessionKind` resolves origin first and answers `"worker"` before it ever looks at the projection (`src/client/session-kind.tsx:295-300`). That order is deliberate — it stops a worker inheriting a parent's mark in the sidebar — and this ruling leaves it in place.

**Why it had no seat.** Stock dsh filters every `origin: 'subagent'` session out of the session list before any row is built (`dsh-client-ui-workspace/lib/client.js:964-965`), and the licensed `sidebar.session.row.leading` cell mounts only inside a row. So the rider's one licensed seat never mounts for a spawned dispatcher; no amount of identity work reaches it. Its own conversation header is the only reachable additive seat.

**Why the identity has to come from the host side.** The child's log contains no durable event that separates a dispatcher child from a worker child: the descriptor is `spawn` for both, no independent preset is selected, and delegated policy overrides are not set. The adapter's mirror is the one place the fact exists — but a projection unit is synchronous with no I/O, so it cannot read the durable `dispatcher_sessions` table itself. Consulting the in-process mirror is the only path that adds no channel.

**The premise this draft has to settle.** ADR-0024's rider item 1 says: "Dispatcher identity already reaches the client through the existing roster mirror (`roster.<sessionId>`), so no new host channel is licensed either." **That premise is dead.** The 0.2.1 port removed the settings-document channel that wrote those keys — the settings service rejects undeclared keys — and `src/adapter/roster-channel.ts` survives on main only as the key grammar, with a file header stating that no channel writes them (`src/adapter/roster-channel.ts:1-9`). Its successor is our own `sessionKind` projection, shipped by tickets 123/130. This draft therefore reads the rider's prohibition as live and its *premise* as superseded: the projection is the successor channel, not a new one.

## Considered options

| Option | Rejected/kept because |
|---|---|
| **Option 1 — select an independent preset at spawn** | **Rejected.** ~260 lines (roughly 200 of composition duplicated from `standard`, ~60 of tests, plus the client lines), and the durable `agent-preset/selected` event it writes into the child's log **cannot be un-written** — the child's history is permanent, so the cost buys a fact we could never retract if the owner reverses. It also still renders nothing: the row is filtered out before a preset could matter. |
| **Option 2 — a new projection key for spawned dispatchers** | **Rejected.** A second key duplicates the fold, the cache row, and the client read path to carry a fact the existing key already means. Decision 1 keeps one key. |
| **Option 3 — a new host channel (the ticket's option (b))** | **Rejected.** The rider forbids it, and nothing here needs it: the mirror exists in the adapter already, and the projection unit can consult it in-process. |
| **Option 4 — fork or vendor stock `dsh-client-ui-workspace` so subagent rows appear** | **Rejected.** Profile-wide fork, breaches ADR-0024 as written, and requires an ADR amendment far larger than the glyph is worth. |
| **Option 5 — mark the child in the licensed sidebar cell only** | **Rejected — physically impossible.** The cell never mounts: no row is built for a subagent child. |
| **Option 6 — the header seat, reading `projectionValues.sessionKind` directly** | **Kept** — the shipped shape. One additive entry, no origin gate at that seat, `resolveSessionKind` untouched. |
| **Option 7 — defer the glyph and record the reduced shape (the ticket's option (c))** | **Rejected by the 2026-10-22 ruling itself**, which asked for parity regardless of initiator. |

## Consequences

- **`sessionKind` moves to `stateVersion` 2.** The `init` now has a source it did not have before, so a v1 checkpoint folded under the old rule would durably cache a spawned child's wrong kind. Per the projection contract the cache row is discarded on the version mismatch and refolded from `init`. **A pre-140 checkpoint is discarded, not migrated** — accepted honestly: a row written before this change loses its cached kind and refolds.
- **Known residual window, recorded not hidden.** A row written by the pre-140 unit is discarded on read and refolds at boot, when the mirror is still cold (it warms at activation). Such a child projects null until something re-derives it — the same window the ticket-138 mirror already had. Rows written from this build forward carry v2 and restore the dispatcher kind across a restart. No new I/O was added to close the older case.
- **One extra client registration.** `src/client/index.ts` gains a second slot inject; the inject-count pins in the client suites move 3 → 4. The sidebar registration and its order are unchanged.
- **The seat count in the docs moves from one to two, each licensed separately.** `docs/surfaces.md`'s inventory gains a header-chip row; the sidebar row's "declined" sentence about the worker marker stays true.
- **Reversal path.** Delete one registration (`dispatcherHeaderGlyphRegistration` and its inject) and one `init` source (the mirror probe) — single seam, no data migration, no durable artifact to clean up. `stateVersion` stays 2 or bumps again; either is a local change.
- **Not covered by this ruling, left untouched:** the message-resume half (ticket 138), the worker marker in any seat, and the ADR-0024 rider's prose rewrite. The rider's body stays untouched per the recorded convention; the dead-premise correction is recorded here and by a dated note on the index row.
