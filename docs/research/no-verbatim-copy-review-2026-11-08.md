## Findings (open follow-ups — not fixed, not filed)

All eight are adapted-copy quality issues. None is a verbatim-reproduction finding. **None was edited in this pass** (ticket constraint); they are listed here for separate authorization.

**F1 — Team-leader wake step 3 names a delivery channel the shipped build does not wire (medium).**
`src/core/policy/prompts.ts:555` (EN) and `:584` (ZH): "use the user-facing send if the user directly ordered something from you". ADR-0009 line 12 records "delivery remains conversational … `deliverToUser` stays unwired"; `src/core/tools.ts:1243-1246` says the shipped plugin wires no separate user-facing send; the suite's own comment at `test/dispatcher-tools.test.ts:633` says "The shipped plugin never wires deliverToUser". The chief-of-staff step in the same block was rewritten in this window from "Deliver through the user-facing send only" to "State the result in your reply to the user — that reply is the channel they read" (`:534`), which matches the code. The team-leader copy keeps the old, false phrasing. The same channel is also named by the chief-of-staff prohibitions at `:629` and `:721` (pre-window bytes) and by the new team-leader prohibition at `:739` (ZH `:658`, `:752`, `:765`); a prohibition is less harmful than a positive instruction, but it still names a channel the shipped build does not have. Owner-supplied text: needs owner sign-off before any edit. PRD §10 line 359 carries the same premise (the leader reports "through `message_agent` rather than the user-facing send alone"), so the requirement and the copy agree with each other and disagree with the shipped seam.

**F2 — ZH peer step 4 points at a parenthetical that is usually absent (low–medium).**
`src/core/policy/prompts.ts:658`: "按发送者的会话 id 发送（见上方发送者名字旁边的括号）". At `5dbf04c`, the EN carried the same parenthetical claim; in this window the EN was corrected to "addressed to the sender's session id shown above" (`:629`), while the ZH kept the old clause. The renderer prints `### name (id)` only when name differs from id (`src/core/policy/assembler.ts:489-496`); a dispatcher sender's `fromName` *is* its session id, so the common case renders `### <id>` with no parentheses. The ZH sentence is therefore false for the peer-sender case and true only for worker senders in a mixed wake.

**F3 — ZH faces never quote the handoff label (low).**
EN names the literal line in all three references: `prompts.ts:349` (class section), `:555` (wake step 3), `:738` (worker-reply step 4) — "the \"Summoning dispatcher session id\" line of your handoff prompt". The ZH faces use three different paraphrases and never the ASCII label: `:373` ("写在你的交接提示里"), `:584` and `:764` ("交接提示开头那一行"). The label is emitted in English regardless of policy language (`prompts.ts:84-91`, prepended at `src/adapter/cordis-dsh-host.ts:4233`), so quoting it in the ZH copy costs nothing and removes the inference.

**F4 — The same `todo_id` parameter carries two nouns (low).**
`src/core/tools.ts:843` (`spawn_worker`): "Links an existing todo entry …". `src/core/tools.ts:1207` (`deliver_result`): "Ledger entry to mark completed once this result is recorded for the user." The latter was added in `afe9846` (Nov 7). The 2026-10-28 pass specifically normalized ledger → todo for this surface (fixes 2 and 4 of that record).

**F5 — A user-facing tool card is written to the dispatcher (low–medium).**
`src/client/overlay.ts:198` (EN) and `:528` (ZH) supply the primary sentence of the `deliver_result` row in the user's chat: "Result recorded — say it in your reply" / "结果已记录——请在你的回复中告知用户". The renderer picks this key when `channel: "reply"` (`src/client/toolviews.ts:940`), which is every shipped delivery. The user reads an instruction addressed to the model; the ZH version even names the reader as 用户 in the third person. The model-facing equivalent is correctly worded (`src/core/tool-results.ts:176`).

**F6 — `steer.pending` and `steer.sent` render identically (low).**
`src/client/overlay.ts:187-188` (EN "Steering {subject}" twice) and `:519-520` (ZH "正在调整 {subject}" twice). Every other verb has a distinct pending/sent pair (spawn, stop, message, deliver), so a steer row can never show that the steer was accepted.

**F7 — ZH priority label regressed to the adjective form (low).**
`src/client/overlay.ts:495`: `"toolview.fact.priority": "优先"`. The 2026-10-28 pass (fix 1) changed 优先 to 优先级 for this concept; the key it corrected (`toolview.field.priority`) no longer exists, and the new fact key reintroduces the adjective form.

**F8 — ZH steer copy uses two words for one action (cosmetic).**
`src/adapter/steer-command.ts:103` (description: "发送中途指示") vs `:105` (success: "排队纠偏") and `:108` (notDispatcher: "纠偏在调度器聊天中进行"), all in `DISPATCHER_STEER_COPY_ZH`.

## Limits and residual risk

A paraphrased-but-not-literal borrow cannot be caught here, and a reference string that no research note quotes cannot be compared at all. "0 hits" means "no overlap with recorded evidence", not "no overlap with the reference".
- **Authorship is commit-and-record based.** Git records a single local identity (TZ) for every commit, so blame yields commit and date, not human-versus-agent authorship. Owner attribution comes from the ticket records, taken at face value.
- **The Reporting provenance is declared, not verified.** Ticket 170 records that the owner directed the pass "after studying the published `dsh-superagent-prototype` for prompt practice" and that the rules were restated in our own words with no text reproduced. That prototype is not in this tree, so no comparison against it was possible; only the declaration is recorded here.
- **Static review only.** No model ran, no UI was rendered, no test or build was executed (ticket constraint). F5/F6 are read off the renderer code, not a screenshot.
- **Client ZH coverage is diff-level.** All 97 added overlay keys and both faces were read; the keys named in F5/F6 were traced to their render sites. Long settings hints were read in full; the rest are short labels.
- **Quality review, not legal clearance.** The human-accepted residual risk under ADR-0018 B9 is unchanged by this record, and this record introduces no new gate, no identifier grep, no continuous-review requirement, and no broad reference inspection.
- **PRD pointer.** `PRD-dsh-multitask-dispatcher.md` §13 M4 now cites this file as a third, bounded pass alongside the 2026-09-19 and 2026-10-28 records; the earlier citations are unchanged.
